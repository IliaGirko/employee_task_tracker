#  Employee Task Tracker

**Employee Task Tracker** — Django-приложение для управления задачами сотрудников, отслеживания их активности и приоритизации.

---

##  Возможности

- Управление задачами и сотрудниками через REST API
- Подсчет активных задач для каждого сотрудника
- Определение "важных" задач, от которых зависят текущие задачи в работе
- Выбор сотрудников для выполнения задач на основе их текущей загруженности

---

##  Модели

###  Employee

- `full_name`: ФИО сотрудника
- `position`: Должность
- `active_tasks_count`: число активных задач (status: `pending`, `in_progress`)

###  Task

- `title`: название задачи
- `status`: `pending`, `in_progress`, `done`, `blocked`: статус
- `priority`: `low`, `medium`, `high`: приоритет
- `due_date`: дата завершения
- `parent_task`: ссылка на родительскую задачу
- `assigned_to`: ссылка на сотрудника

Методы:
- `is_active()` — активна ли задача
- `is_important()` — задача важная, если она `pending`, и её подзадачи `in_progress`

---

##  API Эндпоинты

### `/employees/`

CRUD для сотрудников

### `/tasks/`

CRUD для задач

### `/active_tasks/`

Возвращает сотрудников и их активные задачи (отсортировано по количеству задач):

```
[
  {
    "id": 1,
    "full_name": "Иванов Иван",
    "position": "Разработчик",
    "num_active_tasks": 3,
    "tasks": [ ... ]
  }
]
```

### `/important_tasks/`
Важные задачи (pending, но подзадачи — in_progress) и рекомендованные сотрудники:
```
[
  {
    "Важная задача": "Обновление документации",
    "Срок": "2025-04-25",
    "ФИО сотрудника": ["Иванов Иван", "Петров Петр"]
  }
]
```
## Валидация

- Employee.full_name: не менее 5 символов

- Task.due_date: не может быть в прошлом

## Подготовка к запуску проекта:
1. Установите Docker.
2. Установите Docker Compose.
3. Убедитесь, что Docker запущен и работает.

### Запуск проекта
1. Клонируйте репозиторий:
```
git clone https://github.com/IliaGirko/employee_task_tracker.git -b feature/task02
```
2. Создайте файл .env в корне проекта и добавьте туда необходимые переменные окружения, указанные в файле .env.example.
3. Запустите проект, выполнив команду для запуска в фоновом режиме:

- Для запуска контейнера:
```
docker compose up -d
```
- Для просмотра запущенных контейнеров:
```
docker-compose ps
```
Для просмотра логов всех контейнеров:
```
docker-compose logs
```
- Для остановки сервисов:
```
docker-compose down -v
```
